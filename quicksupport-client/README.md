# Quick Support executable

Windows executable for remote support of computers that do not have the
Tactical RMM agent installed (backend: `api/tacticalrmm/quicksupport`).

When the customer runs it, it:

1. opens a session on the Tactical RMM server and shows a 9 digit support code;
2. downloads the MeshCentral agent from the server and runs it in temporary
   (`connect`) mode in its own MeshCentral device group. Nothing is installed;
3. the technician types the code in the dashboard (**Quick Support** button in
   the top bar) and gets remote desktop, terminal and files through MeshCentral;
4. when the window is closed the agent is stopped, its files are deleted and the
   device is removed from MeshCentral.

Optionally the customer can ask for **permanent access**: the technician
approves it in the dashboard (choosing the client/site), and the executable
downloads and runs the regular Tactical RMM agent installer (`installer.ps1`)
as administrator.

## Build

Uses the C# compiler that ships with Windows (.NET Framework 4.x). No SDK or
Visual Studio is needed (the code is C# 5).

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Output: `dist\trmm-quicksupport.exe`. The icon is `branding\quicksupport.ico`
(generated by `branding\make-icon.ps1`).

## Install on the server

Copy the executable to the server:

```
/rmm/api/tacticalrmm/tacticalrmm/private/exe/trmm-quicksupport.exe
```

or point `QUICKSUPPORT_CLIENT_EXE` in `local_settings.py` to another path. The
dashboard downloads it from **Quick Support > Download**: the server appends
its settings (api url + client token) to the end of the file, so the same
executable works for any server.

Appending data invalidates an Authenticode signature, so a signed build shows
as unsigned after download.

## Settings (`local_settings.py`, all optional)

| Setting | Default | |
| --- | --- | --- |
| `QUICKSUPPORT_CLIENT_EXE` | `<EXE_DIR>/trmm-quicksupport.exe` | executable served by the dashboard |
| `QUICKSUPPORT_CLIENT_FILENAME` | `QuickSupport.exe` | name of the downloaded file |
| `QUICKSUPPORT_API_URL` | `https://<host of the request>` | api url embedded in the executable |
| `QUICKSUPPORT_INSECURE_TLS` | `False` | executable accepts self-signed certificates |

The rest (company name, welcome message, consent prompt, privacy bar,
notification, session timeout, MeshCentral device group) is in
**Settings > Global Settings > Quick Support**.

## Permissions

- Role permission **Use Quick Support** (`can_use_quick_support`): list sessions,
  connect by code, end sessions, download the executable. Existing roles with
  "Use MeshCentral" get it when migrating.
- Approving a permanent access install also needs **Install Agents** and access
  to the chosen site.
- Users limited to some clients/sites only see the sessions they connected to.

## Notes

- The executable endpoints (`/quicksupport/client/...`) are authenticated by
  the client token embedded in the executable and by a per-session secret, and
  are rate limited per ip. The token can be reset in the settings (executables
  downloaded before stop working).
- In `connect` mode the MeshCentral agent captures the screen in its own
  process, which is slow on some machines. MeshAgent PR
  [Ylianst/MeshAgent#476](https://github.com/Ylianst/MeshAgent/pull/476)
  makes it capture in a child process like the installed service does.
